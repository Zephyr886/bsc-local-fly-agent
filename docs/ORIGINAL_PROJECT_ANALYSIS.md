# 原项目结构与核心逻辑分析

## 1. 总体结构

原项目 `FLAP Pulse` 是一个运行在 BNB Chain 上的 FLAP 代币观测、决策与执行系统，主要分为五层：

1. **Next.js / React 展示层**：`app/`、`components/`、`hooks/`。公开页面展示神经元场、行情和成交流；控制台负责受限配置与模拟账户操作。
2. **同源 API 与访问控制层**：`app/api/`、`lib/monitor-proxy.ts`、`proxy.ts`。浏览器不直连 4100 端口；只读状态与写配置分开，控制台叠加隐藏路径、IP、口令、签名 Cookie 等约束。
3. **Node 监控与执行层**：`server/index.mjs` 是主循环。它每秒读取代币状态、价格、区块与钱包余额，每 5 秒扫描成交流，调用决策引擎，再进入模拟或链上执行器。
4. **决策层**：轻量大脑在 `server/fly-brain.mjs`，旧阈值引擎在 `server/score-engine.mjs`，Hybrid V2 的量化门控与纸面账户在 `server/hybrid-v2.mjs`。
5. **Python 全连接组层**：`server/full-brain/` 加载 `vendor/stonkfly/` 的 MaleCNS 数据与控制器，运行 166,700 个神经元、25,582,938 条有向边的重放/实时观察；Node 通过 `full-brain-client.mjs` 与其通信。

支撑目录包括：`scripts/`（构建、回测、迁移、数据处理）、`docs/`（设计与运维说明）、`deploy/`（systemd/nginx）、`db/` 与 `drizzle/`（数据结构）、`public/`/`assets/`（点云和视觉资源）、`vendor/`（第三方 stonkfly 与许可证）。

## 3. 轻量大脑为何是核心

`server/fly-brain.mjs` 不是普通加减分器，而是确定性、可解释、可导入/导出学习权重的状态机：

- PN 感觉输入：多阶秒级收益、30 秒趋势、量能异常、相对滚动中位的位置。
- KC 蘑菇体：64 个 Kenyon 细胞做确定性随机投射和 k-WTA 稀疏编码，同时保留底部/顶部先天感受野。
- APL：对 KC 群体活动做全局抑制与归一化，避免单个极端刺激直接击穿决策。
- DAN：用动作后窗口内的最大有利偏移（MFE）计算奖励预测误差，而非只看终点价。
- MBON：买入与销毁两条通路分别学习、分别归一化，避免共享增益造成方向冲突。
- DN：以推挽差值形成唯一膜电位，竞争性选择 buy / burn / hold。
- 稳态机制：KC 适应、输出慢基线、探索噪声、饥饿、能量和唤醒度共同防止单侧锁死，并控制动作频率。
- 持久化：只保存真正学习得到的 MBON 权重、多巴胺与统计量；导入时校验版本、种子、细胞数量和感觉维度。

## 4. 原执行逻辑

轻量模式下，正膜电位越过阈值触发 `burn`，负膜电位越过阈值触发 `buy`。原项目曲线阶段走 FLAP Portal，迁移后走 PancakeSwap V2；回购使用目标币的真实报价资产，销毁则向黑洞地址转账。所有动作受余额、Gas、滑点、冷却、路由和模式约束。

全脑模拟模式把 MaleCNS 提案与 Hybrid V2 量化方向做一致性检查。Hybrid V2 再施加数据健康、持续趋势、价格位置、动态频率、累计 10% 预算、单笔流动性占比、税费、AMM 冲击与 Gas 约束，并维护 TWAP、纯量化、纯全脑、Hybrid 四套影子账户。

## 5. 本地 BSC 版的保留与取舍

- **完整保留两个决策核心**：`fly-brain.mjs` 与 `hybrid-v2.mjs` 都逐字复制，测试分别校验 SHA-256；PN/KC/APL/DAN/MBON/DN、量化评分、脑/量化共识、动态频率、累计预算、池参与率、价格冲击以及四影子账户全部保留。
- **保留同构运行骨架**：本地观察器生成 5 秒 K 线与成交流，先提供 120 个预热样本，再依次进入脑、Hybrid 特征、七级门控和四账户执行；每个决策周期写入 SQLite WAL，而不是只存在页面内存。
- **有界简化**：不加载 25M 边的 Python MaleCNS，也不部署 Cloudflare/nginx。实盘改为本机加密保险库逐笔解密签名，不提供长期解锁或无人值守签名；原版轻量脑作为本地神经提案源，Hybrid V2 仍负责最终可执行性判断。
- **外部适配而非篡改**：原 Hybrid 影子账内的 `BURN` 含义和记账保持不变；只有通过所有门控后，BSC 实盘边界才把该提案映射为 `SELL`。Flap CA 统一走官方 Portal（曲线期和迁移后 DEX 均支持），普通 V2 CA 继续走 PancakeSwap Router。
- **行情策略**：网页运行时按主项目口径读取 Flap Portal 状态、真实 quote 池储备和 quote→USDT 边际换算；普通代币读取 PancakeSwap V2 池。没有可验证现价时拒绝启动，不用合成数据冒充链上 K 线。CA 种子的确定性行情仅用于无网络自动化测试。
- **真实交易约束**：本地保险库使用 scrypt + AES-256-GCM 加密，密码不保存且每笔重输。真实交易方向不能手选，服务端仅签署当前 Hybrid 已放行、未过期、未使用、额度匹配且绑定一次性授权的交易；回执成功后才消费提案。
